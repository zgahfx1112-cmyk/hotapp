# 移除 B站 内容设计

## 背景
用户要求将 B站相关内容从产品中全部移除，范围覆盖智能推荐与热搜 tab，不仅隐藏展示，还要避免后端继续抓取并让推荐链路再次混入 B站数据。

## 目标
- 热搜数据源不再抓取 `bilibili` 与 `bilibili_pop`。
- 热搜页子 tab 不再出现 B站相关入口。
- 智能推荐页不再消费 B站热搜项。
- 产品文案中不再宣传支持 B站热搜。
- 相关测试覆盖上述行为，防止回归。

## 非目标
- 不清理历史浏览记录、收藏记录、已有缓存文件中的旧 B站数据。
- 不做与本需求无关的平台排序、推荐算法、UI 重构。
- 不处理项目外文档或已废弃 worktree 中的 B站字样。

## 方案对比
### 方案一：仅隐藏前端展示
只改 `public/app.js`，删除 B站 tab 与名称映射。

优点：改动小。
缺点：后端仍抓取 B站数据，推荐链路和接口响应仍可能包含 B站，属于表面移除。

### 方案二：移除数据源并同步清理展示层（推荐）
删除后端 B站数据源配置与解析函数，前端去掉平台名称映射与文案，同时补测试确保推荐/热搜不再出现 B站。

优点：前后端一致，范围小但彻底。
缺点：需要同步更新测试。

### 方案三：全仓清扫
在方案二基础上继续清缓存样例、历史数据、所有文本引用。

优点：搜索结果最干净。
缺点：改动面过大，容易触碰无关文件，超出当前需求。

## 采用方案
采用方案二：移除数据源并同步清理展示层。

## 现状观察
- `hotapp/server.py` 当前定义 `parse_bilibili`、`parse_bilibili_popular`，并在 `PLATFORMS` 中注册 `bilibili` 与 `bilibili_pop` 两个热搜源。
- `public/app.js` 的热搜页子 tab 由 `state.hotItems` 动态生成，平台名称通过 `getPlatformName()` 映射；只要后端不再返回 B站平台，tab 会自然消失。
- 智能推荐页基于热搜池构建内容，若热搜池不再含 B站，推荐页自然不再混入 B站。
- `public/manifest.json` 描述文案仍显式写有“B站”。
- 现有 `test/digest.test.js` 已用 `bilibili` 作为非白名单样例，可保留或微调；还缺少直接约束“平台映射不含 B站”和“后端平台配置不含 B站”的测试。

## 设计
### 1. 后端热搜源移除
修改 `hotapp/server.py`：
- 删除 `parse_bilibili` 与 `parse_bilibili_popular`。
- 从 `PLATFORMS` 中删除 `bilibili`、`bilibili_pop` 两个配置项。

结果：
- `/api/hot` 聚合结果源头不再包含 B站数据。
- 热搜接口错误信息、聚合线程、排序逻辑无需额外改动，因为它们都遍历 `PLATFORMS`。

### 2. 前端热搜 tab 与展示文案清理
修改 `public/app.js`：
- 从 `getPlatformName()` 映射中删除 `bilibili` 与 `bilibili_pop`。

结果：
- 即使未来有异常脏数据混入，前端也不再维护 B站正式命名映射。
- 当前正常链路下，热搜子 tab 会因 `state.hotItems` 不含 B站而自然消失。

### 3. 智能推荐链路保证
智能推荐主链路不单独增加新分支或黑名单。

原因：
- 当前推荐数据来自热搜池与资讯池混合。
- 热搜池上游删除 B站后，推荐页不会再拿到 B站项。
- 额外加黑名单虽可防守，但会引入重复约束，不符合最小改动原则。

### 4. 产品文案清理
修改 `public/manifest.json`：
- 将描述中的“B站”去掉，保持与产品实际支持范围一致。

## 数据流影响
变更前：
B站 API -> `hotapp/server.py` 解析 -> `/api/hot` 返回 `bilibili` / `bilibili_pop` -> 热搜页生成 B站子 tab -> 智能推荐可能消费 B站热搜项。

变更后：
B站 API 调用链不存在 -> `/api/hot` 不再返回 B站平台 -> 热搜页不生成 B站子 tab -> 智能推荐不会消费 B站热搜项。

## 测试设计
遵循 TDD，先补失败测试，再删除实现。

### 测试点
1. 后端平台配置不含 `bilibili`、`bilibili_pop`。
2. 前端平台名称映射不含 B站文案。
3. 推荐摘要逻辑继续忽略非白名单平台，B站样例仍不会入选。
4. manifest 描述不含“B站”。

### 建议测试文件
- 新增或扩展 `test/hotapp-start.test.js`：断言后端热搜源配置不包含 B站键。
- 新增 `test/platform-name.test.js` 或在现有前端相关测试中断言 `getPlatformName` 不返回 B站映射。
- 更新 `test/digest.test.js` 保持 B站样例为非入选平台，作为推荐回归保护。
- 新增轻量测试断言 `public/manifest.json` 描述文本不含“B站”。

## 风险与处理
### 风险一：旧缓存仍含 B站数据
`hotapp/cache.json` 可能残留旧 B站数据，短时间内本地直接看缓存可能仍见旧项。

处理：
- 本次不改缓存文件本身。
- 验证时以重新抓取后的接口结果和前端展示为准。

### 风险二：测试依赖实现细节过深
若直接 import 前端整页脚本，测试环境可能受 DOM 依赖影响。

处理：
- 优先做文本级或纯函数级断言。
- 若现有 `public/app.js` 未导出 `getPlatformName`，测试可基于源码文本断言映射中不含 B站键值，避免扩大改造。

## 验收标准
- 代码中不再存在有效 B站热搜抓取配置。
- 热搜页不再出现 “B站热搜” 与 “B站热门” tab。
- 智能推荐页新加载内容不再出现 `platform` 为 `bilibili` 或 `bilibili_pop` 的项。
- manifest 描述文案不再提及 B站。
- 相关测试通过。
